# 0.7.1 — a local setup keeps working after the first hour

Requires Tenuo Python SDK 0.3.6 or later in the 0.3 series. No policy or state migration.

## Changes

- **Local warrants renew themselves.** When a local session warrant expires, the next tool call re-mints it with exactly the permissions it already had and records the renewal in the receipt log. Edits to `tenuo.yaml` are not picked up; they still take effect only with `tenuo-claude refresh`. Set `auto_renew: false` to make authority lapse at `ttl_seconds` until you run `tenuo-claude up`. Cloud-trigger and managed warrants are never renewed locally, and `tenuo-claude revoke` switches renewal off until the next `refresh`. Renewal reuses the lifetime recorded at the last `refresh`, `init` or `up`; a project set up on 0.7.0 renews with the one-hour default until then.
- **`audit --verify` works on older receipts.** A warrant's expiry is judged at each receipt's own time, so receipts older than the warrant's lifetime verify instead of failing.
- **Policies with `subagents:` compile again.** Subagent warrants are derived with the call Tenuo 0.3.6 requires.
- **Quieter `status` and `check`.** A healthy one-hour warrant is no longer flagged as expiring, and `check` no longer prints an install hint under a passing line.

## Upgrade from 0.7.0

Install `tenuo-claude-code==0.7.1` in the environment your hooks use (`uv tool upgrade tenuo-claude-code`). Nothing else changes.
